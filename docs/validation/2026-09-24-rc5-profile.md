### Public read-back investigation

The documented `pmset -g live` is the same getter as `pmset -g`. The local
Darwin manual and [Apple's published pmset source](https://github.com/aosm/PowerManagement/blob/master/pmset/pmset.c)
show that `-g custom` reads persistent profiles rather than the same current
global SleepDisabled value. It is not an equivalent substitute. The live
getter also enumerates assertions and process names. Its underlying
IOPMCopySystemPowerSettings interface is not a supported public replacement.
No undocumented getter or private API was adopted.

### Ranked next experiments and rejected shortcuts

1. **Lowest runtime risk: paired execution-context benchmark.** Repeat the same
   fixed read-only command, environment, serial pipe capture and child CPU
   accounting as ordinary user and root under comparable conditions. The older
   user microbenchmark averaged about 4.7 ms/read versus roughly 17.1 ms in
   this installed run. This difference is not causal proof. First determine
   whether launch context explains it; any runtime identity change would need
   a separate security and supported-API assessment.
2. **Low safety risk, limited expected benefit: avoid hidden presentation work.**
   Trace body invalidation and model publication costs before changing views.
   The hidden timeline already pauses its timer. The 88 evaluations do not
   prove an expensive timer or justify claiming a specific CPU saving.
3. **Material safety risk: merge renewal validation stages.** Simply removing
   admission reads predicts about 0.488% inclusive CPU at this run's other
   costs, still failing. Reusing admission state for replies loses the existing
   post-admission drift check and is rejected. Any reordering must preserve
   safety sampling, expiry, ownership and genuinely fresh reply observations.
4. **Rejected: slower watchdog, cached success, preferences in place of live
   state, or private APIs.** These do not meet the stated constraints. Even
   deleting both renewal read paths predicts about 0.367% at unchanged other
   costs. This is an illustrative subtraction, not an achievable measurement
   or a universal lower bound.

No runtime optimization has been selected yet. The next work is the bounded
paired read-only experiment, followed by an evidence-based safety decision.
No passing performance claim.
